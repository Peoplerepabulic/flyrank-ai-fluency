## Where the next case study goes

Every finished piece of work gets a case study in **two places**:

1. A `CASE-STUDY.md` file in that project's own GitHub repo (so the story lives
   next to the code), and
2. a link to it from my GitHub profile README's "Selected work" section (so a
   visitor finds it in one click).

## How to add one (the steps, three-beat shape)

1. **Problem** — one paragraph: what real problem did this solve, and for whom?
   No jargon; a non-engineer friend should get it.
2. **What I did** — 3–5 bullets: the key decisions and the hardest part, with
   links to the repo, the design doc, and the evidence (tests, probes, demos).
3. **What came of it** — the outcome: accepted / shipped / what it proves about
   me, plus one honest line about what I'd do differently.

Then: commit `CASE-STUDY.md` to the project repo, add the link to the profile
README, done. Fifteen minutes if the evidence docs already exist — which, for
my FlyRank work, they do.
